# 素材目录

本仓库只发布代码和文档，不发布糖猫原始图片、GIF、生成副本或图标。运行源码前，需要在本地自行准备素材。

## 目录结构

```text
assets/
├─ README.md
├─ local/
│  ├─ 糖猫合集/
│  └─ 日常与悬停/
└─ generated/
   ├─ manifest.json
   ├─ files/
   │  ├─ static/
   │  └─ animated/
   └─ icons/
```

## 本地原始素材

`assets/local/` 保存 PNG 和 GIF 原始文件。素材脚本只读取这些文件，不会修改、覆盖或删除它们。

- `糖猫合集/`：普通动作、现有 GIF、三组动画移动素材、投掷与拖拽素材，以及生成程序图标所需的 `站.png`。
- `日常与悬停/`：日常和悬停专用静态图片。
  - 带数字前缀的文件以奇数编号作为日常，以该奇数加一的偶数编号作为对应悬停。
  - 一个奇数日常可以对应多张使用同一偶数前缀的悬停图。

`日常与悬停/` 中的全部素材都禁止进入普通动作池。如果 `糖猫合集/` 中存在内容完全相同的文件，也会按内容哈希排除。

移动专用素材为 `迈步.png`、`抬腿.png`、`跑.png`、`跑2.png` 和 `动图/跳跳.gif`，不进入普通动作池。`倒立.png` 既是拖拽画面也是普通动作，`飞猫.png` 既是投掷画面也是普通动作。

## 生成运行时素材

先安装 Python 依赖，再生成素材：

```powershell
python -m pip install -r requirements.txt
npm run prepare:assets
```

`npm start` 和 `npm test` 也会在启动或测试前自动执行素材准备。

每次准备素材时，脚本都会先在 `assets/generated-staging/` 中完成处理，再整体替换 `assets/generated/`。生成目录包含：

- 运行时实际使用的静态图片和 GIF 原始副本；
- GIF 逐帧副本、帧时长和循环信息；
- 每张静态图片及 GIF 每一帧的不透明边界和碰撞信息；
- 日常、悬停、拖拽、普通动作、移动、投掷和玩耍角色清单；
- 系统托盘使用的多 DPI 图标。

GIF 逐帧副本用于忠实播放、暂停恢复和逐帧碰撞。生成管线不会产出新的合成 GIF 文件；迈步与跑按 manifest 中明确的两帧静态序列播放。

## 尺寸处理

- 根据不透明区域衡量角色主体，保持原始宽高比，不裁切原图。
- 大部分素材使用自动视觉尺寸；少量异常素材通过 `scripts/asset-overrides.json` 设置人工倍率。
- GIF 使用代表帧中的角色主体判断显示大小，不以动画总画布或所有帧的联合边界判断。
- 自动尺寸和人工倍率处理后，再对全部桌宠素材应用 `80%` 的全局显示倍率；气泡字号和系统托盘图标不受影响。

所有处理只作用于生成副本，不修改原始素材。

## 分享版素材保护

`npm run dist` 不会直接把 `assets/generated/` 放入便携版：

- 只收集 manifest 实际引用的静态图片、GIF 逐帧 PNG 和四档托盘图标。
- 不收录运行时未使用的原始 `source.gif`、图标源文件和其他尺寸图标。
- 正式 manifest 会删除原始来源路径、内容哈希、生成时间和统计信息。
- 页面代码、正式 manifest 和素材共同写入 AES-256-GCM 加密资源包。
- 应用启动时一次性验证并解密到内存，通过内部同源协议按需读取，不主动生成明文临时素材。
- Windows 必须直接读取 EXE 内嵌程序图标，因此由 `站.png` 生成的应用图标是唯一允许明文提取的私有视觉例外。

离线程序必须随身携带可恢复的解密能力，因此该方案只能提高提取门槛，不能抵挡有针对性的进程调试、内存抓取或画面捕获。

## 版本控制

以下目录均由 `.gitignore` 排除，不会发布到代码仓库：

- `assets/local/`
- `assets/generated/`
- `assets/generated-staging/`

不要在 `assets/generated/` 中手动保存文件；下次准备素材时，该目录会被整体替换。
