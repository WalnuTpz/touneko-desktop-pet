# 开发与本地构建

本文从已安装依赖、备好本地素材的工作区开始，介绍修改、验证和生成 EXE 的流程。首次准备工作区按[使用指南](使用指南.md)操作。以下命令均在项目根目录执行，窗口与成品验证使用 Windows PowerShell。

## 修改并查看结果

修改 JavaScript、HTML 或 CSS 后，从托盘退出已有实例，再运行：

```powershell
npm run dev
```

`dev` 直接启动 Electron，使用已有的 `assets/generated/`。修改图片、清单或生成器后，使用 `npm start` 重建素材并启动。

修复交互问题时，从可复现的操作顺序和状态变化开始。例如“双击前先播放单击动作”，需要追踪系统双击间隔、第一次释放、第二次按下和待确认单击的取消过程。渲染进程负责行为，主进程负责窗口与系统输入，预加载接口连接两者；纯计算放在 `src/core.js`。行为机制及参数集中在 `docs/行为设计.md`。

先纠正错误的状态、引用或控制流。外部数据在入口校验，内部沿用已有不变量；错误保留触发上下文，新增处理分支对应可复现的失败。回归测试重现输入和可观察结果。

## 调整素材

### 维护图片与行为的对应关系

`assets/catalog.json` 是 ID、用途和倍率的编辑入口，当前清单使用 `schemaVersion: 4`。ID 使用小写 ASCII 字母、数字与连字符。同一图片可被多个角色引用，例如 `handstand` 同时用于普通动作与拖拽。

| 要修改的内容 | 清单字段及含义 |
|---|---|
| 源素材集合 | `staticAssets`、`animatedAssets` 分别声明 PNG、GIF 的 ID |
| 日常和悬停 | `daily` 中每组的 `idle` 是日常图片，`hovers` 是进入悬停时的候选 |
| 普通动作 | `actions` 声明可以随机播放的动作 |
| 自主移动 | `movement` 定义速度、轴、源朝向和动画 |
| 特殊行为 | `dragAsset`、`throwBehavior`、`playBehavior` 指定拖拽、飞行、落地和玩耍素材 |
| 图标 | `iconAsset` 指定应用与托盘图标的来源 |
| 文案主题 | `dialogueAliases` 将动作 ID 映射到共用主题 |
| 单素材大小 | `scaleMultipliers` 为指定 ID 叠加额外倍率 |

替换现有图片时保留 ID；调整用途时修改对应角色引用。增加或移除 ID 时，同步维护源文件、全部角色引用、文案主题和素材数量测试。生成器检查声明文件、重复 ID、角色引用与源文件内容；重复内容通过同一 ID 复用。

移动动画有两种表示。`type: "sequence"` 按 `frames` 中的 `asset` 和 `durationMs` 播放静态帧；`type: "gif"` 通过 `asset` 使用一份 GIF 的逐帧时长。`sourceFacing` 记录原画朝向，运行时据此镜像；`axes` 决定可选的移动轴，`speed` 使用 DIP/s，即每秒移动的系统逻辑像素数。

### 校准显示尺寸

生成器用 alpha 不低于 8 的像素测量可见边界。静态图片直接使用这条边界；GIF 选择边界高度最接近各帧中位数的一帧作为代表，并列时选较早帧。测量包含图片中的道具与特效，因此宽构图和大特效可以通过单素材倍率调整。

设代表帧边界高度为 `H`，`scaleMultipliers` 中的倍率为 `M`（未指定时为 1），用户大小档位为 `U`：

```text
基础倍率 B = 1          当 180 ≤ H ≤ 200
基础倍率 B = 190 / H    其余情况
manifest.displayScale = B × M × 0.8
运行时倍率 = displayScale × U
```

例如 `H = 300`、`M = 1`、`U = 1` 时，可见高度为 152 DIP。缩放保持宽高比和完整画布，GIF 全部帧共用倍率，帧内的相对位置因此保持一致。

修改倍率后执行：

```powershell
npm run prepare:assets
npm run catalog:assets
```

打开 `build/asset-catalog/`，比较角色比例、宽构图与 GIF 各帧。再用 `npm run dev` 播放相关行为，检查气泡、碰壁与 `150%` 大小时的完整画面。`tests/manifest.test.js` 检查角色映射、边界与窗口容量，角色间的视觉比例和动画衔接通过目录图与真实窗口确认。

生成器将结果写入 `assets/generated-staging/`，成功后替换 `assets/generated/`。manifest 记录画布、边界、帧时长、倍率与角色映射；文件按内容哈希命名。原始文件保留在本地，后续调整仍从源文件和清单开始。

### 使用几何示例测试

在一份独立、已安装依赖的源码工作区运行：

```powershell
npm run test:demo
```

命令先按清单生成带 ID 标识的 PNG 与 GIF 几何图形，再执行完整测试。示例用于验证素材处理和行为逻辑，角色构图与动画观感使用自备图片检查。测试完成后可用 `npm run dev` 查看示例窗口。

示例生成器通过 `assets/local/.demo-assets` 标记识别自己的目录，再次运行会重建该目录。已有自备素材、且没有标记的目录会让生成器报错退出。从示例换成自己的图片时，将整个 `assets/local/` 示例目录移到项目外，重新创建素材子目录并放入文件，再运行 `npm start`。

GitHub Actions 在 Windows 上安装 Node.js、Python 和项目依赖，依次执行 `npm run check` 与 `npm run test:demo`。


## 编辑气泡文案

每个普通动作通过主题取得四条文案，启动开场白单独定义。多个动作共用主题时，在清单的 `dialogueAliases` 中映射；主题内容维护在 `src/dialogue.js`。

1. 修改主题的四条短句或开场白。
2. 更新需要共用主题的动作映射。
3. 生成素材清单、验证主题覆盖，再导出预览：

```powershell
npm run prepare:assets
node tests/dialogue.test.js
npm run docs:dialogue
```

预览位于 `build/气泡文案.md`，按主题展示当前开场白和动作短句。它是本地生成产物，文字来源为 `src/dialogue.js`，主题集合来源为生成 manifest；排版由 `scripts/render_dialogue_doc.js` 维护。

## 验证修改

### 自动测试

完成代码、素材或行为修改后运行：

```powershell
npm run check
npm test
```

`check` 检查 JavaScript 和 Python 源码语法，准备角色素材之前也可执行。

`test` 先重建本地素材，再运行六组测试：

| 验证范围 | 对应测试及覆盖内容 |
|---|---|
| 随机与运动计算 | `tests/core.test.js`：抽取、最近记录、循环、暂停计时、速度和反弹 |
| 文案与素材协议 | `tests/dialogue.test.js`、`tests/manifest.test.js`：主题覆盖、角色引用、帧数据、源内容和尺寸 |
| 资源格式 | `tests/secure-resources.test.js`：加密往返、路径与内容认证 |
| 输入与进程协作 | `tests/renderer.test.js`、`tests/main.test.js`：点击时序、透明区、穿透、环境权重、全屏坐标和初始化 |

定位单个问题时直接执行相应文件，例如 `node tests/renderer.test.js`。测试以生产源码为对象，在 DOM、Electron 和时钟边界设置替身，使用确定性输入验证结果。素材或文案相关测试使用最新生成 manifest。

### 真实窗口

在 Windows 中退出普通运行实例，完成上面的测试后运行：

```powershell
npm run start:smoke
```

命令使用已有生成素材和独立的临时设置目录。成功时退出码为 `0`，终端显示“Electron 冒烟测试通过”；`build/smoke-test/` 保存日常、普通动作、移动和 `150%` 缩放四张截图。逐张检查角色与气泡是否完整。

冒烟通过内部命令验证全屏暂停恢复，并关闭真实的全屏自动隐藏。涉及显示器或窗口的修改还要在普通运行模式下检查：

1. 拖到第二块显示器，观察移动边界和任务栏避让。
2. 在糖猫所在屏幕进入、退出全屏，观察隐藏与原行为恢复。
3. 在另一块屏幕切换全屏，观察糖猫保持当前状态。
4. 两屏使用不同缩放比例时重复上述过程，确认监测对应正确的显示器。

记录所用命令、运行环境和实际结果。WSL 适合编辑和纯逻辑测试，工作副本放在 Linux 文件系统；窗口、托盘、PowerShell 监测与 EXE 验证在 Windows 进行。

## 构建本地 EXE

完成素材校准、自动测试和真实窗口验证后，从托盘退出桌宠，在 Windows 执行：

```powershell
npm run dist
```

命令先运行 `check` 和 `test`，随后构建运行代码、整理加密资源、生成图标，由 electron-builder 输出便携版，再执行包内容校验和最终 EXE 冒烟。成品包含 Electron 与本次素材，双击即可运行；换图后重新构建。

| 输出 | 用途 |
|---|---|
| `release/糖猫桌宠-*.exe` | Windows x64 单文件便携版 |
| 同名的 `.exe.sha256.txt` | 本次成品的 SHA-256 |
| `release/win-unpacked/` | 可直接运行的目录版，入口为 `糖猫桌宠.exe` |
| Windows 临时目录下的 `tangmao-desktop-pet-smoke-output/` | 最终 EXE 生成的本轮四张截图 |

检查便携版截图后，以普通模式双击 EXE，确认托盘、开场白与退出。使用下面的命令核对成品与校验文件：

```powershell
$package = Get-Content -Raw package.json | ConvertFrom-Json
$artifact = Join-Path release "$($package.build.productName)-$($package.version).exe"
Get-FileHash -Algorithm SHA256 $artifact
Get-Content "$artifact.sha256.txt"
```

两处 SHA-256 应一致。资源加密每次使用新的随机量，因此重新构建会得到不同哈希。记录对应的源码提交、构建日期、文件哈希和验证结果，并保留用于重建的本地素材。当前构建未配置 Authenticode 签名。

需要检查中间阶段时使用以下命令：

| 任务 | 命令和结果 |
|---|---|
| 只构建目录版 | `npm run pack`：执行检查、测试、构建及目录版校验 |
| 查看资源整理结果 | 素材已生成时运行 `npm run secure:prepare`，输出 `build/secure-runtime/` 和 `build/secure-runtime-report.json` |
| 重验现有成品 | `npm run verify:secure -- --require-portable`：对照本次报告检查目录版，并确认便携版存在且新于 ASAR |
| 重跑成品冒烟 | `npm run smoke:portable`：直接运行便携版，核对退出状态与本轮截图 |

ASAR 与构建报告摘要不一致，或便携版早于 ASAR，表示产物来自不同构建；重新执行完整 `dist` 流程。素材、主题或帧映射失败时，按报错 ID 修正输入后重跑对应检查。便携版冒烟失败时，结合终端输出和本轮截图定位运行阶段。
