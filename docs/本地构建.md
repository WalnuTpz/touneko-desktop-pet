# 本地构建

本文介绍如何将源码与自行准备的表情包构建为 Windows x64 单文件便携版。仓库提供源码和素材清单，EXE 由使用者在本机生成。素材准备完成后，`npm start` 可以直接运行；需要双击启动时再进行本文的构建流程。

成品包含 Electron 和本次构建的角色素材，运行时无需另行安装 Node.js 或 Python。更换图片后重新构建，新的 EXE 才会包含更新后的素材。

## 准备构建环境

在 Windows 10/11 上准备 Node.js 22.12.0 或更高版本、Python 3.10 或更高版本，并在项目根目录打开 PowerShell：

```powershell
python -m pip install -r requirements.txt
npm ci
```

按 `assets/catalog.json` 准备本地素材：`staticAssets` 中的 ID 放在 `assets/local/static/<id>.png`，`animatedAssets` 中的 ID 放在 `assets/local/animated/<id>.gif`。当前清单为 136 张 PNG 和 21 份 GIF。

输出文件名由 `package.json` 中的产品名与 `version` 组成。产品名为“糖猫桌宠”，作者与公司名为 `Walnut`。构建前确认本地素材和源码已完成调整，并从托盘退出运行中的糖猫。

## 核对替换后的素材

更换图片后，运行 `npm start`，检查日常、悬停、动作、移动和 `150%` 大小下的显示效果，再调整 `assets/catalog.json` 中的倍率。随后从托盘退出桌宠，执行下面的源码检查与窗口验证。

`tests/manifest.test.js` 检查素材数量、角色映射、源文件内容、帧边界和 `150%` 大小下的画布范围。修改清单数量时同步更新统计预期。具体构图与动画衔接通过真实窗口确认，素材倍率计算和检查步骤见[素材说明](../assets/README.md)。

## 验证源码窗口

运行以下命令：

```powershell
npm run check
npm test
npm run start:smoke
```

前两项完成源码检查、素材生成和六组自动测试；第三项启动真实 Electron 窗口进行冒烟。成功时显示“Electron 冒烟测试通过”，并生成 `build/smoke-test/` 中的四张截图。

查看日常、普通动作、移动和 `150%` 缩放截图，确认图片与气泡完整。涉及显示器的改动还要在普通运行模式检查同屏全屏隐藏、异屏全屏与混合 DPI 切换；源码冒烟中的全屏恢复通过内部命令驱动。

## 生成便携版

```powershell
npm run dist
```

npm 自动先运行 `predist`，即 `check` 与 `test`，然后执行以下流水线：

1. 读取生成 manifest，整理运行资源，构建和混淆主进程、预加载与渲染代码。
2. 将页面、样式、渲染脚本、manifest、PNG 帧和托盘图标打成加密资源包。
3. 生成 Windows 应用图标，调用 electron-builder 构建便携版。
4. 校验 ASAR 文件清单、构建摘要、元数据、全屏助手脚本和 Electron Fuses，生成 SHA-256 文件。
5. 直接启动最终 EXE 的冒烟模式，检查退出状态及本轮四张截图。

最终输出为：

```text
release/
├─ 糖猫桌宠-<版本>.exe
├─ 糖猫桌宠-<版本>.exe.sha256.txt
└─ win-unpacked/
```

目录版保存在 `win-unpacked/`，便携版截图位于 Windows 临时目录的 `tangmao-desktop-pet-smoke-output/`。源码冒烟与便携版冒烟使用不同的截图目录。

每次构建随机生成资源密钥和加密随机量，同一源码重新构建后的文件哈希会变化。校验时使用与本次 EXE 一起生成的 `.sha256.txt`。

## 检查本地成品

完整 `dist` 流程通过后，在 PowerShell 中核对文件哈希：

```powershell
$package = Get-Content -Raw package.json | ConvertFrom-Json
$artifact = Join-Path release "$($package.build.productName)-$($package.version).exe"
Get-FileHash -Algorithm SHA256 $artifact
Get-Content "$artifact.sha256.txt"
```

两处 SHA-256 应一致。随后以普通模式启动该 EXE，确认托盘、启动开场白和退出操作，再记录构建源码提交、构建日期、文件哈希及验收结果。

将 EXE 与对应的校验文件保存在一起，保留本次源码、素材和构建记录，以便以后修改或重建。当前构建未配置 Authenticode 签名，生成的是未签名应用。源码使用的 GPL v3.0 许可证随程序放入 ASAR。

## 构建中间结果

需要检查目录版时运行：

```powershell
npm run pack
```

该命令同样运行检查和测试、准备加密资源、生成图标，然后执行目录构建并校验。Windows 下的目录版位于 `release/win-unpacked/`，可运行其中的 `糖猫桌宠.exe`。`pack` 停在目录版校验阶段。

已有当前构建产物时，可以单独重复验证：

```powershell
npm run verify:secure -- --require-portable
npm run smoke:portable
```

前者核对目录版与本次构建报告，并检查便携版存在且新于 ASAR；后者在 Windows 上直接运行便携版，核验本次生成的截图。

`npm run secure:prepare` 只生成 `build/secure-runtime/` 和 `build/secure-runtime-report.json`，需要已准备的 manifest。它适合检查资源整理阶段。完整构建以 `dist` 的最终 EXE 验证为完成点。

## 包内内容与验证依据

ASAR 只含 `LICENSE`、`package.json`、`src/main.js`、`src/preload.js` 与 `assets/runtime.tpack`。页面和渲染资源位于加密包内，运行时 manifest 删除源路径、内容哈希、生成时间与统计字段。GIF 以 PNG 帧运行，源 GIF 留在开发目录。

全屏监测助手放在 `resources/fullscreen-monitor.ps1`，与源码和构建时摘要核对。正式进程启用上下文隔离与 sandbox，渲染进程关闭 Node 集成；Electron Fuses 关闭 RunAsNode、Node 环境参数和调试参数，并启用 ASAR 完整性及仅从 ASAR 加载应用。

构建后的文件清单校验与摘要校验检查“实际装入了什么”；最终 EXE 冒烟检查“成品是否运行并产出本轮截图”。验证报告对应各自阶段。资源保护采用客户端内存解密，应用携带运行所需的解密能力，应用图标嵌入 EXE。

## 处理构建失败

- 素材或文案测试失败时，按输出中的 ID 修正源文件、清单或主题，再运行相应测试。
- ASAR 文件与报告摘要不同，说明目录版和 `build/secure-runtime-report.json` 来自不同构建；重新执行完整构建，使两者同步。
- 便携版早于当前 ASAR 时，重新运行 `npm run dist` 生成对应成品。
- 便携版冒烟只在 Windows 执行。失败时保留终端输出，检查临时目录中的截图时间，再从对应构建阶段定位。

构建记录包含源码提交、构建日期、文件哈希和验证结果，用于将问题定位到实际运行的成品。
